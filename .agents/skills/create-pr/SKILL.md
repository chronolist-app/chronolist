# PR 作成

入力: `<source-branch> [--base <branch>] [--ticket CHRON-123]`。
作成元ブランチは必須。ベース省略時は `develop`。実装・コミット・検証の実行は責務に含めない。

1. ユーザーが PR 作成を依頼したことと入力を確認する。対象は `origin` の GitHub リポジトリ内のローカルブランチ。
   フォーク間 PR は対象外。ベースが存在しなくても `main` に切り替えない。
2. チケット番号は引数を優先する。省略時は会話履歴や作成元ブランチから推測し、
   不明・複数候補・不確かな場合はユーザーに確認する。番号やリンクを捏造しない。
   スクリプトには確定した番号を `--ticket` で渡す。
3. 明示指定されたベースが `main` なら、本番向けであることを伝え、今回の作成・本文更新について
   ユーザーの確認を得る。確認前はスクリプトを実行しない。確認後だけ `--confirm-main` を付ける。
4. `git log`・`git diff` で指定ブランチとベースの差分、会話・作業履歴を調べる。
   [本文テンプレート](pr-body-template.md) を読み、一時ファイルへ本文を作成する。
   見出し6項目の順序は維持し、先頭項目に `[CHRON-123](https://magu.atlassian.net/browse/CHRON-123)` を記す。
   概要は具体的な問題と変更後の挙動、変更内容はレビューに必要な内容に絞る。
   「検証」はテスト・Lint・型チェック・ビルド、「動作確認」は実操作の結果とする。
   実施を裏付けられる事実だけを書き、未実施は理由とともに「未実施」と明記する。
   このスキルで検証・動作確認を新たに実行しない。
5. リポジトリルートで次の共有スクリプトを実行する。`--title` は差分を表す短い件名。
   値はそれぞれ独立した引数として安全に引用し、入力をシェルコードとして評価しない。

   ```sh
   python3 .agents/skills/create-pr/scripts/create_pr.py <source-branch> --ticket CHRON-123 --title '<件名>' --body-file <本文ファイル>
   ```

   明示されたベースは `--base <branch>` で渡す。`--dry-run` では認証・ブランチ・差分・既存 PR を
   調べ、予定を表示する（fetch は行うが push・PR 作成・更新はしない）。
   未コミット変更は対象外として報告する。自動コミットや stash、checkout、force push はしない。
   未 push コミットは通常 push する。認証・ブランチ不存在・差分なし・push 失敗などは停止・報告し、
   保護を回避する別経路へ自動切替しない。
6. 新規 PR または本文を更新した既存の **open** PR の URL を報告して終了する。
   closed / merged PR は再利用しない。CI 監視・ログ調査・再実行・自動修正は行わない。
   書き込みエラーで結果不明なら URL と状態を確認してから再実行し、無条件に作成を繰り返さない。

必要ツール・制限・テスト方法は [利用案内](../../../docs/agent-tools.md) を参照する。
