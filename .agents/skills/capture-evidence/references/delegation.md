# 委譲と代表操作評価

方策決定、曖昧さ解消、確認方法選択、画像評価、最終充足は呼出元が担当する。
子には会話全履歴を渡さず、確定した実行だけを依頼する。
セッションのモデル一覧を確認して指定する。本タスクの利用可能一覧には gpt-6.1-sol がある。
Codex ツールの例: spawn_agent の model: gpt-6.1-sol, reasoning_effort: low, fork_turns: none。
CLI や Claude Code の設定名をこのツール schema と混同しない。Claude は自身の一覧を確認する。
単価未確認なので最安とは断定しない。指定不能/利用不能なら無断で別モデルに替えず呼出元へ返す。
呼出元自身でスクリプトを実行する経路もある。

委譲 packet（実値へ解決して渡す）:

```text
目的: ToDo 入力途中と登録後の証跡
worktree/SHA/dirty 指紋: <確定値>
FE URL/API URL: <確定 origin>
計画 JSON: <検査済み絶対パス>
操作: 新規作成→指定タイトル入力→draft.png→登録→再読込→saved.png
期待状態/確認: draft は入力値、saved は一覧と API のタイトル一致
形式: fullPage PNG、trace 不要
保存先: frontend/e2e-results/<URL hash>/<新規 run ID>/evidence/
実行: frontend で npx playwright test capture-evidence.spec.ts
制約: URL/手順/期待状態を変更せず、逸脱/失敗/利用不能は停止して返す。
自動再試行なし。原因確認後に呼出元が必要時だけ新規実行を指示する。
返却: 終了コード、記録/画像の絶対パス、取得/確認状態、逸脱/未確認。
```

代表操作は draft/saved 2地点。各試行の開始/終了、設定、入力/出力/cache token（取得可能分）、
retry 回数、所要時間、撮影/確認結果を記録する。単価とトークン消費を別に比較する。
料金比較なら確認日付き公式単価・通貨を入力/出力/cache ごとに計算し、再試行込み合計を示す。
ツール時間・コンテナ費用はモデル料金と分ける。安い単価でも消費量と再試行で総額は増える。
スクリプト自体のモデル API 呼出はないが、呼出元/子の消費がゼロという意味ではない。
テレメトリ未取得や現行単価は未確認と記し、推定 token や架空金額を補完しない。

評価列: 操作/試行/設定/取得結果/確認結果/時間/入力token/出力token/cache token/
再試行/単価出典と日付/モデル料金。未取得欄は未確認。
